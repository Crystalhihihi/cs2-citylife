# 交接文档 · 2026-08-20 深夜版

> 写给明天（或任何接手者）：当前状态、怎么验证、已知坑、下一步。设计权威见 `docs/specs/2026-08-16-cs2-living-city-design.md`（v4，含 §12 决策记录与 §13 角色层）。

## 一、当前形态（全部已部署到本地 Mods/CityLife，git 已入库）

**信息层**：自建信息流面板（GameTopLeft 气泡按钮）——LLM 批量帖（人格卡×形态×真实店名锚点×市民真实处境×分区话题）+ 评论区（争论串+续热）+ **连续剧剧组**（M5 v1：4 个具名角色分集推进）+ 板块 tab + 市长发帖框 + 回复 + 拖拽缩放 + 自绘滚动条。作者署名一律真实市民名（特殊注入卡除外）。原版 Chirper 被发布侧 Harmony 补丁根治。

**感知层（本轮新增，"有看头"三要素的素材地基）**：CityChangeSystem 城市变化感知——新公司/公服/公园/地标落成、建筑被拆、新路、人口门槛 → 变化锚点（每炉≤2 条进 prompt）+ 大事件模板快讯。信息流=市长决策的回声壁。

**写回层（M4 活动链，本次重点验收对象）**：
市长发帖说办活动 → 意图解析（LLM 归一化 startHour/durationH/scale/budget）→ **原生弹窗确认（候选全量公园真名 + 地图选点任意建筑 + 时段警示）** → 真扣财政（时长平方级加价）→ 公告 → 下一个整点开场 → 吸引力 ramp + 分批注入 → 实数到场 → 结算（爆棚返 50%/及格 20%/冷场骂）→ 参数恢复。阴间时段（0-6 点）人气系数 0.15 且必挨骂。

**突发层（本轮新增，"大事没人谈论"的根治）**：直采事件组件（火灾=OnFire、车祸/犯罪=AccidentSite.m_Flags，分类学见 `docs/spikes/2026-08-20-event-taxonomy.md`）→ 目击模板帖（"现场直击"，即时）+ **LLM 快讯帖（"城市快讯"本地媒体账号，单帖小炉，requestId 带锚点）** + 写 `LiveContext.LastBreaking` → 下一炉市民集中议论（热议串）。此前 LastBreaking 全库无人写入，热议炉从未触发。

**民意层 v2（本轮新增，活动链逆向闭环）**：负面情绪超阈值（幸福<45/失业>12%/无家可归>5）+1/4 抽签 → 联署快讯 + **怨气热议串**（市民带怨气发帖、评论站队）→ **窗口 6h 内市长发帖=回应**（平息）；超时未回应 → 市民真实聚集**市政厅/地标**（SignatureBuildingData 查询，prefab 名含 CityHall 优先；注入 petitionScale×写回档位，复用活动链原语）→ 3h 散去结算。触发权全在执行层，v1 只动舆情不动数值；与活动链互斥防双注入；凌晨超时顺延 7:00。配置：settings.json 的 petition* 五项（`petitionDebug:true` 可绕情绪阈值测试）。

## 二、验证清单（按序）

1. 重启游戏，日志（`Logs/CityLife.log`）无 CRITICAL、有 `[Filter] 原版 chirp 过滤补丁已应用`
2. 市长发帖："明晚 8 点办个周末市集，预算中档" → 弹窗出现，**候选地点是"方位·真名"且数量随城市公园数**（不再恒 4-5——旧版拿锚点采样池当场馆池，公园上限 4 是根因）
3. **地图选点**：点"在地图上选点"→ 卡片收成提示条 → 点任意建筑（商店/学校/住宅均可）→ 卡片回来显示"地点：XXX（改回列表）"→ 确认后公告/开场/聚集都落在该建筑；选点中 Esc 只退选点不取消卡；"改回列表"可切回候选
4. 确认后日志看 `[Money] 财政 -XXX`（真扣）→ `[Event] 已排期 明晚 20:00` → 到点 `[Event] 开场` + 场馆人群聚集
5. 结算帖：爆棚/及格/冷场 + 下一炉市民议论活动（【活动结果】上下文）
6. **突发热议**（本轮核心）：等城里出火灾/车祸/盗窃（或 developerMode 点火）→ 突发帖出现 + **下一炉市民集中议论此事**（热议串、评论多）——此前 `LiveContext.LastBreaking` 全库无人写入，热议炉从未触发；`[News] 突发（fire/crime/accident）` 日志同步有记录
7. 对照组（可选）：凌晨 3 点办一场——红色"时段阴间"警示，到场惨淡，结算必挨骂
8. 面板交互回归：拖拽/缩放/滚动条/贴底/中文输入不豆腐块；原版 chirp 仍被过滤
9. **民意层**（本轮新增）：settings.json 写 `petitionDebug:true`（绕情绪阈值）→ 冷却过后日志 `[Petition] 触发` + 信息流出联署快讯与怨气热帖（评论≥8 站队吵架）→ ①窗口 6h 内市长发帖：结算帖"市长回应了…"+下一炉议论；②不发帖等超时：`[Petition] 标志性建筑名录`+现场帖+市政厅/地标前真实人群（petitionScale 150×档位）→ 3h 后散去结算帖；无标志性建筑的城日志记降级只走舆情

## 三、已知待校准项（玩的时候留意日志）

- `[Anchor·校准]`：公司盈利分布（阈值 200/50 是猜的）与业态词命中率——攒半小时日志可校准
- 吸引力 boost +100 是初估值（`EventChainSystem.BeginRunning`），看人群到场速度是否偏弱/过强
- 晚高峰 API 偶发 >240s 尖峰（已调 420s；再超时有日志 `[LLM] 一炉失败`），面板短暂安静属供给侧现象
- `[News] 突发（fire/crime/accident，进热议|仅快讯）`：频率两档分离——快讯帖按类限流（火灾 4h/车祸 6h/犯罪 8h/全局 1h，游戏小时），全城热议单独闸门（默认 12h 一次，`breakingHotHours` 可调）。盗窃/车祸是高频事件，"仅快讯"是常态，"进热议"是稀罕
- `[Pick]`：地图选点日志（"选中的不是建筑"/"冷却中"都是正常拒绝，卡片不动）
