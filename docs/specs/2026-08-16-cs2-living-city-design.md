## 0. 项目定位

- **名称**：CityLife / 市民圈（CS2 市民官方称谓 Cim）
- **许可证**：MIT（最大化社区贡献意愿：CLI 适配 + 事件包靠社区生长）
- **平台**：CS2（官方 Paradox Mods 代码 mod 路线，IMod + ECS，**不走 BepInEx**）。**目标版本不定死**：以开工时最新大版本为准；当前参考版本 1.6.0f1（Iceflake Studios 维护）
- **LLM 供给**：不接裸 API key——**双轨供给**：订阅制 code CLI（Kimi Code 先行，接口抽象，社区可接 Claude Code 等其他 CLI）或按 API 计费的接入。两轨共用同一条缓存纪律（见 §4 M3），订阅制省额度、计费制直接省钱

## 1. 目标与非目标

**目标**：用 LLM 驱动的虚拟社交平台替换 Chirper，让城市"活起来"。

- 市民/商家/政府部门发帖、评论、互相吐槽甚至对骂；内容锚定游戏真实模拟状态
- 放大视角时视野内出现**日常对话**气泡（街头语域，与平台语域分离）
- 玩家在平台以市长身份发言**真实影响游戏**：宣布活动 → 市民聚集 → 交通拥堵 → 舆情发酵的连锁
- **AI 是硬前提**（2026-08-20 定案，§12 #24）：本 mod 本质就是 AI mod——无供给时信息流静默，不为无 AI 玩家设计；T0 模板仅作显式开启的兜底（settings.json）；MUTE = 一键停 AI

**非目标**：不做每市民独立 LLM agent；LLM 不直接改写模拟数值（单向阀门）；不做 TTS；不做跨存档角色延续；**不替换游戏原生个体 AI**（市民/游客的行程与行为本体属游戏侧，mod 改的是流量与叙事）。

**核心原则**：算得准的全给执行层，LLM 只做两件事——把结构化上下文变成文本、把玩家自然语言变成结构化意图。

**反馈回路原则（v3）**：舆情不能只被看见，还要算数。标准回路——刺激 → 不同画像的市民真实移动（带距离衰减）→ 涌现后果 → 舆情镜像。每个实体事件必须配"注意力引导"（热搜/公告 + 点击聚焦）：**感知率是一等设计目标**，做了没人看见等于没做。

**社区优先原则（v3）**：代码注释、扩展点标注与适配文档是一等交付物。后期内容生态（事件包/CLI 适配/翻译）靠社区生长，一切设计为"不写代码也能扩展"让路。

## 2. 总体架构

```
┌────────────────────────── CS2 进程内（C# mod, IMod + ECS）──────────────────────────┐
│  GameBridge（版本敏感面集中层）                                                        │
│   ├─ 读：ECS 查询 / 游戏系统聚合数据 / 事件检测（降频错峰）                               │
│   └─ 写：定向 TripNeeded 注入 / 吸引力提升 / prefab 参数 / RandomTrafficRequest / CustomChirps │
│                                                                                      │
│  内容引擎 ── 话题源统一（执行层从真实数据检测话题）                                       │
│   ├─ 平台语料池（社交语域：帖子/评论/对骂剧本/热搜）                                     │
│   └─ 闲聊语料池（街头语域：两人对白/即景吐槽，供气泡）── 两池语料分开生成                  │
│   生成分层：T0 模板(~70%,零token) / T1 批量一炉出串(~25%) / T2 明星人格(~5%)             │
│                                                                                      │
│  展示侧                                                                               │
│   ├─ 信息流面板（cohtml React 自建；MVP 期先用 CustomChirps 发原版 Chirper）             │
│   └─ 气泡 overlay（氛围层：C# 投影 → binding 推送 → React 绝对定位 div）                 │
│                                                                                      │
│  写回层（单向阀门）：EventSpec/情绪标签 → schema 校验 → 分档有上限的数值映射              │
│   └─ 原语执行器库 + 声明式事件包（JSON/YAML，社区可扩展）                                │
│                                                                                      │
│  CLI 网关（后台线程）：队列/优先级/冷却/过期丢弃/重试/token 统计/MUTE                    │
└──────────────────────────────────────────────────────────────────────────────────────┘
                     │ 进程调用（异步，全 one-shot，绝不阻塞模拟线程）
                     ▼
        LLM 供给（code CLI headless one-shot 或 API 计费接入；接口抽象 ICliProvider）
```

**关键架构决策：全 one-shot**。所有调用都是 mod 组装好完整 prompt（含候选实体列表）→ 单次返回文本/JSON。不建 MCP 桥、不多轮。理由：批量内容生成的成本/延迟/缓存命中全部最优；MCP agent 模式留作后续调试扩展口。

## 3. 执行层 vs LLM 分工总表

| 职责 | 归属 | 说明 |
|---|---|---|
| 游戏状态读取/蒸馏/事件检测 | 执行层 | ECS + 阈值，`frameIndex % 128 != offset` 错峰 |
| 话题检测与热度排序/衰减 | 执行层 | 话题源统一喂给平台池与闲聊池 |
| T0 内容（招聘/开业/通报） | 执行层 | 100% 模板 + 数值插槽 |
| 平台帖/评论/对骂文本 | LLM one-shot | 一炉出整串（1 帖+N 评 或 完整骂战剧本），执行层滴灌释放 |
| 闲聊语料 | LLM one-shot | 独立池，街头语域，去新闻化更耐放，3-5 游戏分钟补一炉（15-20 条） |
| 作者分配/语气立场 | 执行层 | 抽签器防风格坍缩（MC 项目 E9 验证过的机制） |
| 气泡剔除/投影/分配/防抖 | 执行层 | **展示零 token**，与镜头操作完全解耦 |
| 市长发言意图解析 | LLM one-shot | → EventSpec（映射到已注册事件包 + 抽参数），失败追问 |
| 所有数值写回 | 执行层 | 原语执行器，分档上限，见 §6 |
| 明星人格每日评估 | LLM one-shot | 低频 + 随机抖动防齐发 |
| 人格/记忆存储检索 | 执行层 | 压缩摘要链；RAG 后续增强且必须后台化（ExpandMemory 主线程卡 500ms 教训） |
| 成本/去重/过期/兜底/MUTE | 执行层 | 状态摘要去重；游戏加速自动降频停 AI；过期请求丢弃 |
| 人群移动触发 | 执行层 | 事件包五旋钮（触发源/画像/半径/规模/时段）→ 定向 TripNeeded 注入，见 §4 M6 |

## 4. 模块分解

### M1 GameBridge（读侧）

- 版本敏感面全部收敛于此，其余模块只依赖其稳定接口
- 读取三档模式：高频遍历 IJobChunk（范本 InfoLoom）；偶发 EntityManager（范本 CitizenEntityCleaner）；城市级聚合直读游戏系统（范本 CS2MCP RequestHandlers）
- 关键数据点位（2026-08-19 已对本机 Game.dll 做元数据初验，详见 spike 报告；开工时仍按当前版本复核）：
  - 市民 `Game.Citizens`：`Citizen`（年龄段在 `CitizenFlags.AgeBit1/AgeBit2` 2bit → `CitizenAge{Child,Teen,Adult,Elderly}`，生日 `m_BirthDay`；`CitizenFlags` 还直接含 Tourist/Commuter/Homeless/Education 位，**人群画像过滤成本极低**）/`HouseholdMember`/`Worker`/`Student`/`TravelPurpose`；聚合 `CountHouseholdDataSystem`（30+ 只读属性：AverageCitizenHappiness/UnemploymentRate/HomelessnessRate/TouristCitizenCount/年龄教育结构，已初验）
  - 公司 `Game.Companies`：`WorkProvider`/`Employee` buffer/`CommercialCompany`；**利润组件已确认（spike 关闭）**：`Profitability{m_Profitability:Byte, m_LastTotalWorth:Int32}` 可直接读取；UI 侧盈利因子拆分（Employee/Renter/Efficiency/TaxRates…）可做"为什么亏"的商家话题素材；备选代理弃用
  - 交通 `Game.Vehicles`+`Game.Pathfind`+`Game.Net`；无现成拥堵组件，按 lane 车辆数自建；寻路为队列制（`PathfindQueueSystem`），注入代价表现为寻路排队而非崩溃
  - 地价/污染 CellMap：`LandValueSystem`/`GroundPollutionSystem`/`NoisePollutionSystem`（读前 `deps.Complete()`）
  - 天气 `ClimateSystem`（temperature/precipitation/isRaining/isSnowing/classification 全套只读属性已确认）；事件 `Game.Events` + `EventJournalSystem`（城市事件日志直接当新闻源；**已确认公开 `eventEntryAdded` 事件回调 + `eventJournal` NativeList，读侧零轮询**）
  - **街头事件钩子**（吃瓜群众触发源）：`AccidentSite`（交通事故一等系统）/`OnFire`/`CrimeVictim`，已初验存在
  - 外部连接：`OutsideConnection` + `TrafficSpawner` + `RandomTrafficRequest`（结构化外部流动的生成通道），已初验存在
- 纪律：查询 OnCreate 缓存；排除 `Game.Tools.Temp`/`Game.Common.Deleted`；`RequireForUpdate`；`gameMode => GameMode.Game`

### M2 内容引擎

- **双池同话题源**：平台池（社交语域）+ 闲聊池（街头语域）；话题由执行层统一检测，两路生成各自成文
- `Post{id, authorArchetype, topicId, text, createdAt, expireAt, targetEntity?, pool}`；Topic 带热度分与衰减
- 一炉出串 + 按游戏时间滴灌（分散释放更真实）；对骂 = 一次调用生成完整剧本
- 区域 = **话题维度**（区域话题挂区域实体，区域内气泡优先取本区话题），不是分配维度
- **市外作者**：画像带 `isExternal` 标记（"外地网友"/旅游博主/邻城市民），参与评论本市话题（景区帖"求地址"、宰客帖"幸亏没去"）；零模拟成本，混入综合流带标识，不单设板块。与写回层真实游客流量双向镜像：流量喂舆情（景区拥挤→"全是人"），舆情喂流量（口碑→spawn）
- **风格卡体系（v3.1）**：风格=**语域滤镜，只管"怎么说"不管"说什么"**——话题永远由城市状态统一供给，严禁把卡写成话题笼子（"工人只谈油价"是反面教材，三天必重复）。卡=名字+≤50 字语域描述+禁区；生产流程=LLM 一次性离线蒸馏初稿+人工审校（AI 蒸馏 AI 用），内置中英各一套（平行创作非翻译：贴吧↔Reddit、小红书↔Instagram 精致风）。**玩家配置接口=JSON 数据文件**（内置卡包+`ModsSettings/CityLife/personas.json` 覆写/新增，schema 进贡献文档，重开生效）；卡库进 prompt 稳定头吃缓存，运行时零 LLM 成本。与语气分档正交：嘴臭类卡在"放开骂"档才启用，且永远受"对事不对人"硬线约束。**只分城区/画像（工业区/CBD/老城区/开发区，与区域话题轴合流），永不分人种**（刻板印象雷区+国际发布审核风险）
- **热点同步（v3.1）**：①**日历同步（默认开）**：季节/节气/开学/年末/春运/入伏，零风险零成本（快照已有季节温度）；②**热点蒸馏（可选开关，默认关）**：每游戏日低频一炉，把当前互联网情绪**蒸馏成无专名无政治的生活话题种子**进话题池（低权重），开关注明"内容源自现实互联网、已脱钩"；③直引现实热点永久拒绝：沉浸断裂+撞内容红线+存档馊梗+仅 CLI 轨可搜索（供给依赖）
- T2 明星市民：见 §7

### M3 CLI 网关

- `ICliProvider` 接口抽象：双轨供给——订阅制 code CLI（Kimi Code 首发实现）或按 API 计费的接入，社区可扩展（README 提供适配指南）。两轨成本逻辑统一：**缓存命中**
- **传输层备选（v3 调研发现）**：进程调用之外，Kimi Code 另有 `kimi web` 长驻本地 REST/WebSocket 服务——免每次进程起停开销，one-shot 语义不变。M0 CLI spike 对比两种传输的延迟/稳定性后定网关默认方案
- **缓存纪律（v3）**：prompt 一律"固定前缀 + 动态尾部"组织——头部逐字节稳定（禁时间戳/随机 ID），全部动态内容压到尾部。CLI 的系统 prompt + 工具定义天然是稳定前缀，mod 自己的 prompt 头部也必须满足同样的稳定性才吃得到服务端缓存
- 进程内后台线程调起 CLI headless one-shot；队列/优先级/冷却/过期丢弃/有限重试（timeout/429/5xx）
- 全局小并发（默认 2-3）；游戏加速自动降频/停 AI；状态摘要去重
- prompt 组装：分段 + 优先级 + token 预算两阶段裁剪（先压缩后裁剪）+ sanitize 防注入 + **输出语言 = 游戏语言**（随玩家游戏语言，发布即中英）
- 全量请求/响应/token 统计日志（含 cached token 观测，验证缓存纪律是否生效）；MUTE 模式一键纯模板零 token

### M4 信息流 UI

- 骨架 fork NotificationLooker；脚手架 `create-csii-ui-mod`；C# `UISystemBase` + React `cs2/api`/`cs2/modding`
- 形态：仿真人社交软件——**默认单列综合流**（替代 Chirper 的本分，"刷"的手感）+ 顶部板块 tab（同城/招聘/商家/吐槽/公告/热搜）+ 市长发帖框
- **评论区**：热评 2-3 条（热度=点赞数+作者权重）+ "展开全部"，展开后分页/虚拟滚动；滴灌释放的新评论带插入动画
- 性能纪律：`UIUpdateState.Create(World, N)` 模拟帧节流；新帖走增量 event binding；高频用 `useValueRef`/`useReducedValue`
- 原版 Chirper：MVP 期用 CustomChirps `PostChirp` 并存；M2 上线后 `ChirperUISystem.Enabled = false`（UI 模块路径运行时 `findModule` 探测）
- **spike 项**：cohtml 输入框的中文 IME 支持必须 M0 期实测（市长发言依赖中文输入）

### M5 气泡 overlay（氛围层）

路线 A：C# `Camera.main.WorldToScreenPoint` 投影 → `ValueBinding` 推 `{entity,x,y,scale}` → React 绝对定位 div。

**锚定与跟随**：气泡锚定实体并跟随，锚点分三类——市民头顶（~1.8m 偏移）、车辆车顶、建筑楼顶/门口。C# 每 10-15Hz 重算投影推送，React 侧 CSS transition 补间，视觉连续跟随不跳变。

**场合覆盖**（市民个体不可见时锚到载体）：

- 街上行人：锚头顶
- 私家车：锚车顶，司机视角内容（堵车吐槽与真实交通数据联动）
- 公交/地铁：锚车厢或车站——候车人群是天然多人对话场景
- 建筑内：锚楼顶/门口，内容=楼内人的声音，按建筑类型分话题包：住宅（房租/邻居/学区）、商店（生意/差评）、办公楼（加班/老板）、工厂（班次/工资）、学校医院各自话题包
- 闲聊池按**场合标签**分类；匹配顺序：锚点类型 → 区域话题 → 市民状态，三层过滤取一条

**多人对话**：一炉生成多角色剧本（A/B 两人 2-4 轮，或群体 3-5 人，一次调用）。执行侧先定"对话锚点"（车站/店门口/公园），再绑定附近共位市民为参与者，轮流在各自头顶冒泡；不做随机路人隔空喊话。

**持续时间**：按阅读量动态——基础 2.5s + 字数系数（约 4 字/秒），钳制 3-12s；对话串连播（上条说完下条接）；镜头失稳或锚定实体离开视野即淡出。参数全部进设置页。

**大小**：屏幕空间近似恒定大小（不随缩放等比缩小），两档微调 + 远距离透明度渐隐；限宽 ~220px、限字 ≤40 字两行。（备选：固定像素大小，M3 实测后定）

**其余已定**：启动防抖（镜头稳定 3-5s 激活）；上限默认 8 条可调；视锥+距离剔除；开关双保险（全局开关 + 建造工具激活自动隐藏）；纯氛围层——hover 展开全文，点击聚焦（`focusEntity` 绑定），不跳帖子；降级预案：退为"选中市民时显示气泡"。

**内容管道 v2（2026-09-09 定案，详见 §12 #48）**：闲聊池升级为**双炉**——话题创建炉（水位触发：新鲜库存 <15 才开炉，一炉产 30-50 条，治"参考面窄"）+ 闲聊炉（3-5 游戏分钟一炉产对话片段；节拍锚游戏时间，暂停零成本、倍速同速放大）。内容哲学**人为主、场景为调料**：主材=真实市民处境矩阵（是谁/在干嘛/从哪来到哪去/乘什么/何时/天气季节，执行层组装零 LLM）；"路边的东西"=环境圈摘要（四叉树半径查询+聚类蒸馏 ≤3 条有戏点：店内/车站人气>事件>景点；原版无排队概念，用 CurrentBuilding/候车组件读人气；"名店"存疑拿掉）。多人对话=对话锚点成组（车站候车/店内 ≥2 人真名单绑定，一炉一剧本 2-4 轮，同屏 ≤2）。剧情=单场叙事基本盘+连续剧角色串场（主炉副产物台词，零额外调用）。社区拓展：topics.jsonl 覆写/追加（抄 eventpacks 模式）。上文"闲聊池按场合标签分类/三层过滤取一条"被本段取代。

### M6 写回层与市长事件链

**单向阀门**：LLM 输出结构化意图 → schema 校验 → 分档有上限的确定性映射。效果永远是执行层**近似映射**，不是字面实现。

**事件包架构（开放式解析的落地形态）**：

- **原语执行器库**（C#，我们写）：**定向聚集人群（TripNeeded 定向注入：人群画像过滤（年龄/在业状态/财富）+ 距离衰减抽样 + 分档人数上限 + 分批错峰注入）**/吸引力调整/预算增减/需求微调/交通注入（RandomTrafficRequest，含定向外部车流）/全体幸福度脉冲/**旅游口碑（游客 spawn 率 + 景区吸引力微调，范本 Time2Work TouristSpawnSystem）**……每个原语自带参数上限与冷却
- **人群响应系统（v3 统一抽象）**：所有"人群真实移动"场景是同一个系统的五个旋钮——**触发源 / 人群画像 / 响应半径（距离衰减）/ 规模上限 / 时段窗口**。不做 N 个定制系统，一个原语参数化全覆盖
- **事件包**（JSON/YAML 数据文件，社区可写）：匹配描述 + 参数 schema + 调用的原语（含五旋钮参数）+ 公告/评论 prompt 模板 + 平衡上限。社区扩展"逆天发言"支持不需写代码
- **首发事件包样例（v3）**：
  1. **市长宣布活动**（烟花节）：官方公告 → 定向注入 → 拥堵/营收涌现 → 舆情跟进
  2. **商家打折促销**：老年画像响应率拉满 + 全城管辖（距离衰减弱），年轻画像仅本区——"老年人隔老远都去"
  3. **吃瓜群众**：原生事故/火灾/犯罪触发 → 周边空闲人口（失业/非通勤时段）小规模聚集 → 平台"图文直播"
  4. **谣言囤货**：平台谣言帖发酵 → 超市抢购潮、停车场爆满 → 官方辟谣 → 潮退。**唯一由平台自发的人群移动闭环**
  5. **旅游洪峰**：节假日脉冲客流（spawn 率拉档位上限、酒店满房、口岸拥堵），配官方公告引导注意力
- LLM 映射不上任何事件包 → 降级为纯舆情事件（平台热议无实体变化），玩家看到"目前做不到"反馈
- 危险操作（如会透支财政的发钱）→ 弹确认框，玩家坚持则执行，后果由引擎真实模拟（当天感谢、三天后服务崩了挨骂）

**注意力引导（v3，与事件包同级的设计地位）**：任何实体事件触发的同时，热搜/公告必须同步把玩家镜头引过去（`focusEntity` 点击聚焦）。人群移动事件的感知率 = 发生频率 × 玩家注意到的概率，没有引导等于没做。

**旅游口碑循环（写回侧特色玩法）**：执行层聚合景区相关话题情绪 → "旅游口碑分" → 分档上限内调整游客 spawn 率/景区吸引力 → 游客真实到访 → 酒店/商业营收涨 → 反哺新话题；口碑差反向掉游客。**把原版贫弱的旅游系统变成玩家可经营的玩法循环**（1.6.0 旅游系统现状需实机确认，spike 项）。**边界（v3）**：mod 改的是游客的**流量与叙事**（来多少、何时来、从哪来、来了议论什么），不替换游客**个体 AI**（行程/动线/拍照属游戏侧，替换违反"加 System 不改游戏"哲学）。

**市长点赞**（玩家互动机制，只设赞不设踩——想打压走发言渠道）：
1. 舆情层：被赞内容热搜加权，NPC 跟评玩梗（"市长认证的好店"）
2. 写回层：被赞市民幸福度小脉冲；被赞商家 24-48h 客流微升（分档上限内）
3. 防刷：同一目标只生效一次；每游戏日软上限，超出只剩舆情效果
4. 明星市民记忆"市长给我点过赞"，成为后续互动素材

**市长事件链实例**（"明晚 8 点中央公园烟花节"）：解析 EventSpec → 场地挂 `SpecialEventData` → 官方号发公告 → 提升吸引力+寻路休闲偏置 → 开场前分批错峰注入 `TripNeeded{Leisure, priority=128}`（**分批注入规避寻路性能悬崖**）→ 拥堵/商家营收为引擎涌现 → 舆情跟进（下雨则切"冷场"剧本）→ 活动结束后恢复（**必须有恢复逻辑**）→ 写入明星记忆

### M7 持久化

人格/记忆/话题/内容池随存档序列化（范本 Traffic `TrafficDataMigrationSystem`）；卸载 mod 后存档正常加载、自定义数据重置。

## 6. 数值红线与内容安全

**写回分档**（设置页，玩家可调）：

| 档 | 幅度 | 说明 |
|---|---|---|
| 体验 | ±5% | 纯氛围微调 |
| 正常（默认） | ±10-15% | 可感知不破坏平衡 |
| 疯狂 | ±30% | 大规模聚集+交通冲击，带明确警告文案（可能交通瘫痪/服务崩溃） |
| 自定义 | 滑杆 | 含完全关闭写回（只留氛围） |

影响面：心情/人流/交通可直接；**环境走间接**（污染网格被原生系统重算不可直写，走垃圾堆积、Game.Events 原生事件）。

**内容安全三层护栏**：

1. prompt 层（可配置）：语气分档（全年龄/默认/放开骂）+ 红线清单——**对事不对人**（可骂"这个税加得离谱"，不可攻击玩家本人）；不碰现实政治/种族性别；**绝不生成怂恿自伤内容**
2. 后置过滤层（硬编码不可关）：LLM 输出过确定性过滤，命中红线丢弃换模板
3. 细粒度开关：吐槽商家/吐槽规划/吐槽市长分别可关

情绪配比跟随真实城市状态：城市治理好则主流是真夸，治理烂才被骂惨——AI 忠于模拟而非为毒舌而毒舌。mod 描述页+设置页附免责声明（内容虚构、AI 生成、与玩家本人无关）。

## 7. 明星市民

- **产生（四级成名体系，热度分由执行层确定性计算，LLM 只负责发声）**：
  - **L0 当事人**：事件主角被话题引用（"当事人表示…"），用完即弃，零成本
  - **L1 一夜网红**：单事件热度够高 → 临时账号火 1-3 游戏天，话题沉寂即消失；只有临时画像，无人格卡/记忆/维护成本
  - **L2 正式明星**：候选池内热度**多次**累积过阈值才升级，获得人格卡 + 记忆 + 每日评估资格
  - **过气降级**：L2 连续 N 游戏天无新话题 → 降级回普通市民，保持明星池新鲜（还能产出"过气网红复出"梗）
- **玩家干预**：可星标任意市民直接升 L2 + 编辑人格卡
- **数量**：L2 默认上限 15，设置可调 5-30（人格维护成本线性涨）；L1 不占名额
- **记忆**：压缩摘要链（每日凝练 ≤50 字长期印象，RimMind-Memory 模式）；向量 RAG 留作后续增强，必须后台化
- 人设参考：城市规划博主（专业喷路网）/本地大V/杠精/热心大妈；大事件连续追踪评论形成"连续剧"
- 明星是 NPC 自发事件的最佳载体：网红探店帖火了 → 第二天店门口真实排队（定向注入联动）

## 8. 成本模型

- 供给：双轨——玩家已有 code CLI 订阅（会员制，边际成本远低于按 token 计费），或按 API 计费接入；**两轨的成本关键都是缓存命中**（§4 M3 缓存纪律）
- 节拍：平台池每 1-2 游戏分钟一炉；闲聊池 3-5 分钟一炉；明星每日一次。**生成速率与镜头操作完全解耦**
- 参考量级：一晚 3 小时 ≈ 100-150 次 one-shot，API 等价 ¥1-3/晚，会员额度内几乎无感（**待 M0 CLI 链路实测验证**：延迟/输出纯净度/cached token/429 率）
- MUTE 模式零成本可玩

## 10. 风险清单

1. 气泡 overlay 无开源先例（最高技术风险）→ M3 独立排期 + 降级预案
2. 公司利润组件：2026-08-19 元数据初验存在（`ProfitabilitySystem` 等），ILSpy 级复核降级为例行；备选"岗位空缺率+客流"代理保留
3. cohtml 中文 IME 未验证 → M0 spike；失败则发言走面板外接文本方案
4. 翘班优先级抢占/大规模寻路未压测 → spike 已提前至 M0；疯狂档规模分级 + 按人口/帧率自动降级
5. LLM 输出 JSON 不合法（RimTalk 最高频报错）→ schema 校验+重试+模板兜底
6. UI binding 随版本漂移 → findModule 探测 + feature flag
7. 内容出格 → 三层护栏（§6）
8. 存档膨胀 → 记忆压缩，内容池只存近 N 条
9. **CLI 供给链（v3）**：分发门槛（玩家须装并登录 CLI）/ 跨 session 缓存命中未实测 / 订阅速率限制 / CLI 版本漂移 → M0 脚本实测 + MUTE/T0 兜底保证"无 AI 也值得装"；`ICliProvider` 文档化留社区扩展口

**核心立场（2026-08-20 玩家与拷问会共识）**：LLM 在游戏里扮演**角色**，不是内容生成器。角色三判据——有判断力、有连续性、有后果。信息流/评论区/气泡全部退位为"角色的发声器官"。
