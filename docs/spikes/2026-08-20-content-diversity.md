# Spike 报告：内容质量归因与抗坍缩调研（公告腔/评论区腔）

> 日期：2026-08-20 ｜ 对象：生产同款 PromptBuilder + 内置 9 卡 + 硅基流动 deepseek-ai/DeepSeek-R1（temperature 0.8）｜ 样本：假快照（人口 3543/失业率 27.4/幸福度 66/雨/夏）连发 4 炉 × 6 条 = 24 条，4 次 API 调用（预算 6 次内）
> 结论先行：玩家反馈属实但**病因高度集中**——A/B 类共 8 条（33%），其中 **weibo、zhihu 两张卡贡献 6 条**；根因是卡面语域描述把"谢邀体/有一说一/结尾升华"写成了逐字模板，模型照单执行。次要病因：话题粒度太粗（24 条全围着雨转）+ 无跨炉记忆（同义重复 3 组实锤）。修法以"改两行卡面 + 一行前缀体裁约束"为最高性价比。

## 1. 实测口径（与生产一致）

- 复现工程：`logs/content-diversity-spike/`（一次性，已删），`Compile Include` 复用 `src/CimLife/Llm/*.cs`、`Content/{Persona,PromptBuilder,CitySnapshot,Topic,ContentDirector,BatchParser}.cs`、`Util/JsonMini.cs`。
- 话题序列复刻生产 `ContentDirector.DetectTopic`（同话题不连发退回日常）：**Rain → Daily → Rain → Daily**。
- 作者分配复刻生产 `PickAssigned` 抽签轮换（9 卡轮询、每炉 6 席）。
- 供给：4/4 成功；promptTokens 451/454/451/453（**固定前缀逐字节稳定，缓存纪律达成**）；responseTokens 1182-1649；延迟 62-85s/炉。

## 3. 多样性粗测

**首 4 字完全相同：3 组共 7 条（29%）**

1. 「有一说一」×3：#3 / #12 / #21（weibo 三炉逐字同开头）
2. 「姐妹们，雨」×2：#11 / #20（xhs）
3. 「雨滴敲窗」×2：#9 / #18（crystal 跨炉同开头，且意思也一样）

放宽到 2-3 字前缀还有：「谢邀」×3、「姐妹们」×4（含串味 2 条）、「加班」×2。

**句式模板感最强的 3 个模式**

1. weibo「有一说一 + 书面语总结 + 价值判断（值得点赞/城市韧性）」：3/3 全中，全落 A。
2. zhihu「谢邀 + 客观来说 + 结尾升华」：3/3 全中，全落 B。
3. xhs「姐妹们 + 雨天宅家做点心 + 幸福感」：#2 热可可/#11 烘焙/#20 甜点，三炉同义换皮。

**跨炉同义对（无记忆的直接证据）**：炉1 zhihu vs 炉3 zhihu（雨水净化空气×2）；炉2 vs 炉3 crystal（雨滴敲窗×2）；炉2 vs 炉3 guide（茶馆安利×2）。**24 条全部围着雨转**——Daily 炉也不例外，因为 Daily 话题文案"日常，没有大事"零素材，模型只能抓【城市此刻】里的雨。话题粒度过粗 + 无历史反馈，正是"大规模生成内容坍缩"担忧的小样本预演。

## 4. RimTalk 抗坍缩策略调研（jlibrary/RimTalk@main）

**prompt 组织**（SillyTavern 式 preset，`Source/Prompt/PromptManager.cs`）：System 段（Base Instruction 角色扮演规则 + JSON 格式 + 全部相关 pawn 档案）→ **Chat History 段** → User 段（`PromptService.DecoratePrompt` 注入对话类型/状态/时间/日期/季节/天气/位置/环境/财富）。情境注入粒度极细：主 pawn 档案 Normal/Full 级（role/背景/特质/健康/人格/心情/思绪/社交/装备），配角降 Short 档省 token（`Source/Service/PromptService.cs` BuildContext/CreatePawnContext）。

**防重复机制**：① `Source/Data/TalkHistory.cs`——每个 pawn 独立保存 user/AI 消息历史对（上限 ConversationHistoryCount×2，先进先出），**每次请求全量随 messages 回喂**，模型看得见自己说过什么；② `Source/Service/TalkService.cs` GenerateTalk——`status == pawn1.LastStatus && RejectCount < 2` 直接拒生成，状态没变就不说话。

**批量还是单发**：**单发**。一次请求 = 一场对话（流式响应里解析多条 turn，`Source/Service/AIService.cs` ChatStreaming），从不在一个请求里要 N 条独立内容。

**措辞约束**：无"禁止公告腔"类明文。`Source/Data/Constant.cs` DefaultInstruction 走正向锚定："Role-play RimWorld character per profile"、"Keep dialogue short (1-2 sentences)"，再按角色给行为锚点（Prisoner: wary, hesitant…）。

**可移植做法（按可搬程度排序）**

1. **历史回喂防同义**（TalkHistory.cs）：已发内容的摘要随请求回喂。我们的批量 one-shot 无会话，等价做法=执行层把最近 N 条已发帖摘要拼进 prompt 动态尾部（见整改 #5）。
2. **状态未变拒生成**（TalkService.cs RejectCount）：与我们设计文档"状态摘要去重"同思路，可加强为"同话题+同状态摘要 → 跳过本炉"。
3. **人格蒸馏的卡面标准**（Constant.cs PersonaGenInstruction）："Include: how they speak, their main attitude, and **one weird quirk that makes them memorable**. Be specific and bold, **avoid boring traits**"——49 张内置人格各带 chattiness 权重。我们修卡面时照此标准：写说话方式和怪癖，**不写可复读的口头禅**。
4. **主/配角信息分档**（PromptService.cs InfoLevel.Short/Normal/Full）：一炉里可以只有"主角"拿具体素材，其余给粗信息——对应我们的"每炉各条切入角度不同"（整改 #4）。
5. **正向锚定 > 负面清单**（Constant.cs DefaultInstruction）：RimTalk 不写禁令也腔调稳定，靠的是"扮演这个人"。反证我们的教训：卡面写了"谢邀体"就会被逐字执行——**卡面每个字都是点单**。

## 5. 整改清单（按 预期收益/改动成本 排序）

约束遵守：话题仍由执行层统一供给；风格卡只管语域；prompt 维持固定前缀 + 动态尾部（BuildHead 逐字节稳定，一切动态内容压尾部）。

1. **修两张问题卡的卡面（成本：两行字符串；预计消灭 6/8 非 C 条）**——`src/CimLife/Content/Persona.cs` k_Builtin：zhihu 卡删"谢邀体/结尾升华"，改"逻辑分明爱讲道理，像发帖不像答题，偶尔甩个冷知识"；weibo 卡删"张口有一说一客观来说"，改"热点嗅觉、短句锐评、爱抛结论但说人话"。按 RimTalk quirk 标准（§4-3）审全部 9 张卡：凡是能被逐字复读的口头禅都删掉。副作用：head 字节变 → 服务端前缀缓存重建一次，无妨。
2. **BuildHead 加【体裁】硬约束（成本：一行前缀文案；覆盖全部卡含玩家自定义卡）**——`PromptBuilder.BuildHead`（`PromptBuilder.cs:17` 起）追加："【体裁】每条是自己主动发的帖子，不是回复、答题或公告；禁止'谢邀''作为一名市民''近日我市'式开场，禁止总结陈词和升华结尾。"前缀内追加不破坏缓存纪律（启动拼一次）。
3. **Daily 话题执行层补料（成本：小；治"全员写雨"）**——`PromptBuilder.DescribeTopic` + `ContentDirector`：Daily 文案"日常，没有大事"太穷，改为执行层维护轮换生活引子池（菜价/通勤/加班/邻里/周末/遛弯），每炉抽 1-2 个拼进话题行，如"日常闲聊（引子：菜价、通勤）"。话题供给权仍在执行层，不违反分工。
4. **分配行加"切入角度"轴（成本：中；破炉内同模板）**——`ContentDirectorSystem.PickAssigned` + `PromptBuilder.BuildBatch` 尾部：角度小池（吐槽/自嘲/安利/观察/求助/感慨）每炉为 6 条各抽一个不同角度，【分配】行写 `1=tieba(吐槽) 2=xhs(安利) …`。角度是语用轴不是话题笼，与风格卡正交；动态尾部不碰前缀。
5. **已发摘要喂回尾部去重（成本：中；灭跨炉同义，"大规模坍缩"的正面解法）**——RimTalk TalkHistory 的批量 one-shot 移植：`PostPool` 维护最近 ~10 条已发帖摘要（每条截首 12 字），`BuildBatch` 加参数拼尾部"【已发过，禁止重复意思】……"。LRU 有界，尾部增量 ~150 字。
6. **入池前查重兜底（成本：中；最后手段，前 5 条失效时的保险丝）**——`PostPool.cs` / `BatchParser` 后处理：与近 N 条首 8 字相同或字符 3-gram 重合率 >0.6 的条丢弃、回退 T0 模板。纯执行层零 prompt 成本，但丢弃=浪费已付 token，故排末位。
